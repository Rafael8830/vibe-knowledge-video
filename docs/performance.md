# 渲染提速纪律：一部片只该渲一遍半

> v2.3 实测数据（1920×1080，单机）：页面渲染 17–55ms/帧；截图 JPEG 105ms / PNG 344ms；管道模式合计约 11 帧/秒。**一部 130 秒的片子（3900 帧）单进程约 6 分钟，不该更久。** 如果超了，对照本文档找原因。

## 一、渲染顺序：从便宜到贵

成本从低到高的四级渲染，**永远从上一级开始，上一级没过关不进下一级**：

1. **页面直开**（0 成本）：浏览器打开 index.html 实时预览，调运动手感。
2. **静帧/拼图**（秒级）：`--stills` 看细节、`--sheet 16` 看全局、`--motion a b` 看转场。**每做完一站就看一次。**
3. **片段**（分钟级）：`--from/--to` 只渲改动的段落，换场景参数后先渲这一段确认。
4. **全片**（一次）：只有四级全过才渲全片。**禁止**"渲一遍全片看看效果"。

## 二、改动 → 重渲范围对照

| 改了什么 | 重渲范围 |
|---|---|
| 某站内的数字/文字/颜色 | 该站的时间区间（`--from/--to`） |
| 某站进场/出场时刻 | 该站 ± 出入场的重叠半秒 |
| 字幕文字 | 字幕是全屏层——**只需重渲字幕出现的帧**，不是全片 |
| 全局层（底色/漂移/字幕样式） | 全片（没办法，但只该发生一次） |
| 场景绘制代码 | 引用该函数的站 |

## 三、速度规则

1. **中间渲染一律 JPEG**（`--jpeg 92`）：PNG 编码 344ms vs JPEG 105ms。PNG 只给最终归档。
2. **成片用 `--pipe`**：帧不落盘直通 ffmpeg（约 11 帧/秒），省掉几百 MB 的帧文件和两次磁盘 I/O。`--pipe out.mp4` 直接出无声片。交付级质量默认 JPEG 95；调效果时用 `--jpeg 92` 更快；要无损归档帧就去掉 `--pipe` 用默认 PNG 全量渲（慢 3 倍，参考引擎的标准路径）。
3. **机器富余时 `--jobs 3`**：三进程并行（每进程一个浏览器渲一段）。**内存不足 4GB 可用时降到 `--jobs 1`**——4 进程在 8GB 机器上会因内存失败（实测），失败信息是 "Connection closed while reading from the driver" 或 x264 malloc failed。
4. **中断用 `--resume`**：跳过已存在的帧继续渲，不要从头重来。
5. **一次浏览器渲一段**（渲染器已内置）：逐帧循环里不要反复开关浏览器；但也别把整片塞进一次浏览器会话（内存会涨）。
6. **音频与视频分开合**：BGM 用 synth_bgm 生成 wav，最后一条 ffmpeg 命令混流。响度归一用两遍式 loudnorm（第一遍 `print_format=json` 量测，第二遍带 measured 参数 + `linear=true`）；**alimiter 默认自动回电平，压不住峰值，用 volume 增益代替**。
7. **系统内存 < 3GB 时**：先关掉大内存应用（浏览器标签、聊天工具），x264 加 `-x264-params rc-lookahead=0:ref=1:threads=1`。

## 四、常见拖慢原因对照

| 症状 | 原因 | 解法 |
|---|---|---|
| 每帧 > 2 秒 | PNG 截图 | 换 `--jpeg 92` |
| 页面 render 本身 > 100ms | 每帧重建渐变/shadowBlur 滥用/上千粒子逐个开阴影 | 渐变缓存成离屏画布；辉光交给统一出帧；粒子用 fillRect |
| 整片 > 15 分钟 | 全片重渲了不止一遍 | 按第一节顺序自查：哪级没过就跳到全片了 |
| 渲到一半进程消失 | 系统内存耗尽 | 分段 + `--resume`；渲前关大应用 |
| 4 进程并行失败 | 每个浏览器约 500MB，内存不够 | `--jobs 2` 或 `--jobs 1` |

## 五、与七步流程的对应

- 第 5 步（代码实现）：用页面直开 + `--stills`。
- 第 6 步（渲染合成）：`--pipe` 出无声片 + synth_bgm + 混流，**全片只渲一次**。
- 第 7 步（自检）：qa_check + `--sheet`；修复后按第二节的对照表**只重渲对应段**，用 `--resume` 续渲。
