# 发布指南：从成片到数据复盘

> 第 7 步自检通过只是"可以做"，发布前还有一道运营关卡。发布不是终点——48 小时后的数据决定下一期怎么做。

## 一、发布前检查清单

**内容与事实**
- [ ] `qa_check.py` 六维全部 ≥ 8 分
- [ ] 人工看图改图至少两轮（`--sheet` / `--stills` / `--motion`），毛病表清空
- [ ] 屏上每个数字都有出处（notes/事实表可查）；模拟与示意已标注
- [ ] 结尾有声明卡 + 学术引用卡；全片无水印、无未授权素材
- [ ] 只读字幕通顺；静音看画面能懂每一段

**包装**
- [ ] 标题是在**问观众**的（"为什么你……""你……吗？"），而不是在陈述知识
- [ ] 封面图缩到 1/4 大小，主标题仍一眼可读；封面文案不剧透反转
- [ ] 发布标题格式：`Vibe知识大赏 | 《片名》一句钩子？`
- [ ] 发布正文：用片子前 30 秒的字幕连成一段话（钩子讲到第一个结论），不剧透后半
- [ ] 话题标签：`#vibe知识大赏` + 3–5 个主题标签
- [ ] 评论区置顶：学术引用 + "本片由 AI 代码生成，无实拍素材"（可信度的第二次加分）

**技术**
- [ ] 上传版规格正确：1920×1080 / 30fps / 时长与分镜一致
- [ ] 上传版**不带音轨**（BGM 在平台曲库里选，不把有版权的音乐渲染进片子）
- [ ] 片名卡、结尾引用卡在手机竖屏缩略图下可辨认

## 二、发布后 48 小时：只看三个数

| 数据 | 看什么 | 说明什么 |
|---|---|---|
| 完播率 | 整体比例 | 叙事是否撑住了全片 |
| 划走时间点 | 观众在第几秒离开 | 精确定位出问题的段：开头走 → 钩子弱；中段走 → 模拟段节奏拖；结尾走 → 反转不够 |
| 互动 | 评论里反复出现的"那为什么……" | 下一期的选题库 |

把三个数记进自己的一张表，一行一期。

## 三、数据差 → 先查叙事，不查画面

经验规律：**画面再精致也救不回叙事的失败。** 数据不好时按顺序排查：

1. 和观众无关？（选题四项打分的第一项没过）
2. 没有悬念或悬念解太早？（定律 2）
3. 中段变成知识罗列、没有转到"你"？（定律 6）
4. 反转只有一层，或每层太弱？（定律 3）
5. 都不是 → 再看节奏（某段超过 30 秒没新东西）和画质问题。

## 四、按数据定方向

做满 5 期后横向比较：哪个题材方向（社交、学习、人性、身体、创作……）的完播率最高？下一批选题向那个方向倾斜；同时回头看 `structure-bible.md` §1 的四项打分，给"高完播方向"的题放宽其他项的门槛。

## 五、更新仓库

每期做完，把可公开的部分（分镜表、事实表、踩到的坑）PR 到 `examples/`——它同时是你的作品集和这份 skill 的测试用例。
