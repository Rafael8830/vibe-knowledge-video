# v2.0 升级说明（完整版）

> 版本：2.0.0 ｜ 日期：2026-10-25 ｜ 兼容性：**完全向下兼容**，v1 的所有用法、命令、模板都不变；本次全部为**增量新增**，未删除或改写任何既有章节的语义。

## 一、这次升级解决什么问题

v1.0 的能力集中在两件事上：

1. **风格规范**——五区布局、配色字体、动效参数、视觉母题库（`style-guide.md`）；
2. **生产流水线**——七步流程、渲染/配乐/合成/自检四件套脚本。

用 v1.0 能稳定产出"看起来像"的片子。但反复实战后暴露出一个结构性短板：**它教了"怎么长得像"，没有教"怎么让观众看懂"**。具体缺口有四个：

| 缺口 | 后果 |
|---|---|
| 没有"讲解设计"方法论 | 画面容易做成**配图**：粒子流、抽象网格放在哪条片子都成立，观众看完说不出"因为……所以……" |
| 字幕稿没有文体规范 | 容易写成口播稿删减版：句子长、寒暄多、术语裸奔、满屏强调 |
| 结构层只有六段式模板 | 缺悬念埋设时机、反转叠法、常驻读数、中段转到"你"、结尾回扣等**叙事纪律**；选题没有筛选标准 |
| 质检只有机器关 | `qa_check.py` 查统计异常，查不出"观众看不看得懂"；没有人工看图改图的工具和毛病对照表 |

v2.0 针对这四个缺口，新增四份方法论文档 + 三个渲染器看图模式 + 全流程接入点。所有新增内容均为本仓库原创撰写的通用方法论表述。

## 二、新增文件清单

### 2.1 `references/visualization-design.md` — 讲解设计（最重要的新增）

决定片子"好不好懂"的文档，建议最先读。内容：

- **配图与讲解的分界线**：一个残酷自测——把这镜画面放到别的题材里还能用吗？能用就是配图。附带两类画面的判别特征。
- **概念→形象的六级提问**：本身是东西？是过程？是量？是心理感受？是规律？都不是→不画只上字。每一级给出处理办法。
- **形象加固三问**：生活锚 / 换尺度看 / 让它坏一次。
- **每一镜的三道自检**：这是什么（日常的词）/ 在干什么（字幕里那个动词）/ 观众明白了什么（与上一镜不同的一句话）；以及"遮住字幕还成立吗"的加分检定。
- **六种呈现动作**：让观众动手 / 照句子演 / 小题现场跑 / 同版式对照 / 收进一张图 / 停住亮字；外加"回场""合体"两个贯穿动作。
- **哪些句子不配新画面**：按"这句话在干什么"给处理对照表，目标占比约 1/5。
- **一个比喻用到底**：全片单一核心比喻的纪律与理由。
- **分镜表七列格式**：呈现动作列 + "观众明白了什么"列，表前表后各有一组说明项和自查清单。

### 2.2 `references/copywriting-rules.md` — 字幕稿规范

把字幕稿当作独立文体来规范：

- **量**：每分钟 18–24 句、中文 ≤ 20 字/句、无字幕时间占 25%–40%（写稿时就留出来）。
- **句式工具箱**：前后半句翻转、破折号放答案、每 4–6 句一个问句、一句话写一个人的细节、"不是A是B"只留论点、对观众说"你"、数字精确到能上屏、末句是片名回声。
- **禁用清单**：寒暄预告、总结腔、口头禅，出现即删。
- **用词纪律**：核心比喻当词汇表用；同一东西全片同一叫法。
- **强调的克制规则**：一句最多强调一处；连续三句至少两句素色；错误/警示内容用另一套色且全片不破例。
- **事实与出处**：每站一个可核对锚点；示意/假说/传闻的标注方式。
- **定稿交验格式**：一行一句带时间区间的表（即分镜表前两列）+ 三条自查。
- **标题/副题/发布文案**规范。

### 2.3 `references/structure-bible.md` — 结构圣经

叙事层的纪律，与 `narrative-templates.md`（段落模板）配合：

- **选题四项打分**：钩子/故事线/可模拟/反转，任何一项弱就换题。
- **三种骨架**：历史接力 / 反常现象+模型 / 隐喻+重新解读，各自的适用题材和关键要求（历史接力必须有"悬着的线"）。
- **标准时间轴**：以 130 秒为基准的七段划分，每段有硬性要求（第 0 帧有字幕、片名 6–24 秒、悬念 30–90 秒后解、读数常驻……）。
- **十条叙事定律**：片名不第一个出、悬念定时解、反转 2–3 层、常驻读数、实物佐证、中段转到"你"、一个模型用到底、结尾开脱不说教、场景不换字幕推进、每 20–30 秒纯画面段。
- **反转的叠法**：惊讶层→机制层→照进自己层；最大揭晓配全片唯一一次最强强调。
- **常驻读数设计**：把核心概念做成一个"仪器"，每个新例子都拿它量一次。

### 2.4 `references/quality-gate.md` — 质量门

机器质检（`qa_check.py`）之外的人工关卡：

- **看图工具**：`--sheet` / `--stills` / `--motion` 三种模式的标准看图顺序。
- **毛病对照表**：14 条"看到什么 → 多半因为 → 改法"（主体太小、遮字幕认不出、发白发糊、硬边、贴纸感、小字压主体、伸进字幕带、转场说不清、推拉镜头漂移后猛冲、又暗又空……）。
- **两轮修复流程**：列毛病 → 修 → 重截同样时刻 → 确认修好且没改坏；至少两轮。
- **终检三遍 + 门槛表**：静音遮字幕看、只读字幕看、八维度门槛逐条过。
- **数字纪律**：先算后写、屏上计数是真的（固定种子+查表回放）、模拟标注、结论数字来自计算、进阶的 `window.selftest()` 断言约定。
- **交片诚实条款**：交付附"不满意清单"。

## 三、脚本升级：`scripts/render_frames.py` v2.0

原有功能（全量渲染、`--preview`、`--scale`）**行为完全不变**，新增三个只读看图模式：

```bash
# 全片均匀 N 帧拼成一张带时刻标签的总览图（看全局节奏与风格统一）
python3 scripts/render_frames.py index.html review/ --duration 130 --sheet 16

# 指定时刻拼总览图（检查关键节点）
python3 scripts/render_frames.py index.html review/ --duration 130 --sheet 3.5 18 62

# 原尺寸静帧（检查字号、重叠、辉光细节）
python3 scripts/render_frames.py index.html review/ --duration 130 --stills 18.3 62.4

# 转场区间均匀 12 帧拼图（检查转场中间有没有说不清的帧）
python3 scripts/render_frames.py index.html review/ --duration 130 --motion 61.5 64
```

输出：`review/sheet.jpg`、`review/still_<时刻>s.png`、`review/motion_<起>-<终>.jpg`。拼图模式只产出检查用图，不产出帧序列，几秒内完成，适合"每做完一站就看一次"的迭代节奏。

## 五、升级后的完整工作流（对照）

```
第 1 步 选题核实     + structure-bible §1 四项打分
第 2 步 剧本         + visualization-design（形象先行） + copywriting-rules（文体）
第 3 步 分镜表       + 呈现动作列 / 1-5 不画自检 / structure-bible 十条对照 / 数字纪律
第 4 步 用户确认     （不变）
第 5 步 代码实现     + 先做最难的一镜并过三道自检
第 6 步 渲染合成     （不变；渲染器新增三种看图模式备用）
第 7 步 自检交付     + qa_check（机器） + quality-gate（人工看图，至少两轮） + 终检三遍 + 诚实清单
```
