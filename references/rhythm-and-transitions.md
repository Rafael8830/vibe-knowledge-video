# 开场、声画节奏与同元素转场

适用于音乐驱动的知识动画，也可按题材借鉴到演示等视频；口播/访谈优先服从话语和剪辑意图，允许合理硬切。不固定红圈、道具、颜色、BPM 或秒数，不保证留存或传播效果。

本文件规定默认知识片的节奏与转场方法。用户选择某个扩展视觉世界时，仍保留该世界限定的动作和辅助转场范围；例如情绪世界的局部禁用项不反向变成默认知识片的全面禁令。叙事模板中的“拍”是信息单元，不等同音乐节拍。

## 开场焦点

Brief 写清“第一眼看哪里”和“什么动作把视线引过去”。从第 0 帧进入动作，在第一秒形成明确落点；视觉冲击可来自尺度、遮挡揭露、运动方向或明暗，不必堆特效。检查 0 / 0.3 / 1 秒与实时短片：遮住字幕仍能定位焦点；飞页、闪白、背景动作不争抢它。镜头快速运动后保留看清主体的机会。

## 节奏事件表

先写内容草稿，确定配乐来源，再分析实际文件的乐句、重拍、抽空和段落。音频经删段/拼接后重建成片时间，不直接沿用原曲时间，不用固定 BPM 生成均匀网格冒充实测拍点。

普通解释句自然展开；只选少数关键词或转折强化。半句可从重拍前约 2–3 秒试起，以音乐和阅读速度调整，不能为等拍空拖；画面可提前承担铺垫。重拍时要检查“关键词真正可读”和“动作到达揭晓状态”，而非只检查动画开始时间。声音需要预起或延后时记录偏移与原因，试听再定。

| 字段 | 含义 |
|---|---|
| id / start / reveal / end | 唯一标识、铺垫起点、成片揭晓重拍、完整句结束；满足 start < reveal < end |
| before / after / beforeEn / afterEn | 两段中英文；英文不能提前透露后半句 |
| actionPeak | 动作到达关键状态的时刻，例如翻面露背或书签落定，而非运动起点 |
| sfxStart | 音效起点；通常和 reveal 共用时间，必要偏移显式记录 |
| 可读区间 | 从后半句完全可见到字幕退出的区间；按字数、双语和手机尺寸检查，不能只计算整句挂屏总长 |

`assets/template.html` 中 `CUES` 为单一数据源，`VibeTiming.cue(t, cue, fps)` 用绝对时间判定阶段；`CUES` 中的秒数按帧率统一量化。音效程序读取由同一份 `CUES` 导出的 JSON，不再手填另一套拍点。`actionPeak` 可晚于/早于 reveal，但需有创作原因并检查实际感知；默认同帧。

使用现有 Playwright 页面导出：`events = await page.evaluate("window.exportCueSheet()")`，将 `events` 写成 JSON 供音效程序读取；`sfxStart` 是最终采样放置时刻。视频用 `render(frame / fps)`，音效用 `round(sfxStart * sample_rate)` 定位，避免分别四舍五入多次。

Remotion 路线同样共享事件数据，以 `useCurrentFrame() / fps` 得到 t 后调用纯时间判定逻辑；函数放进项目模块，不依赖 `window`，也不另建一套拍点。渲染、预览与逐帧检查继续使用上游 Remotion 路线。

## 转场交接表

| 字段 | 含义 |
|---|---|
| 承接元素 | 跨镜持续存在的同一元素，如线、圆、卡片或局部细节 |
| 前形态 → 后形态 | 几何、位置、尺寸、颜色与语义如何连续变化 |
| start / handoff / end | 开始、主体交接、完成；全部为成片时间 |
| 前场退出 / 后场展开 | 非承接元素何时撤走、后场道具如何出现 |
| 辅助方式 | 遮挡、淡化、闪白或黑场的具体用途；无需要则不用 |

前场先退出其他元素，承接元素由一个绘制函数持续持有；交接前后不各生成一个相似但独立的道具。后场从变形后的元素展开，不把两个完整构图做长交叉淡化。调度调用必须覆盖整个变形区间，不能提前截断。允许短暂、有意的局部叠加。

`VibeTiming.transfer(t, transition, fps)` 返回旧场非承接元素透明度、承接元素变形进度和新场非承接元素透明度。默认旧场在 handoff 前退完，新场在 handoff 后展开；承接元素始终单独绘制。它只管理时间，作者仍需实现真实的形态连续。简单交接可从 0.2–0.5 秒试起，复杂变形按需要延长，不设统一上限。

淡入淡出可用于局部收束或层次交接，闪白可强化少数关键落点，黑场可表达停顿与结束；不要每镜套用，不用它们掩盖未实现的变形。画面安静不等于失效，允许明确的阅读停顿和情绪留白。

## 短样验收

1. 首秒实时播放并查看 0 / 0.3 / 1 秒，焦点明确且未被辅助元素遮住。
2. 卡点检查揭晓前一帧、目标帧和后一帧，以及整段播放；关键词到目标帧已可见，动画到达揭晓状态；中英文没有提前泄露或闪断。
3. 转场检查 start / handoff / end 及相邻帧；没有残字、双重承接元素、无意空帧或位置/形态跳变。静音实时播放仍能跟住视线。
4. 对同一个 t 打乱顺序渲染，结果应一致，保持 `render(t)` 无帧间状态。
5. 手机上检查完整句阅读时间；正常速度试听验证音乐、动作、音效的感知同步。只能检查代码与波形时标记“待试听”，不能据此给声画对位满分。
6. 自动帧差低只列待复核时间点；不强制给留白加粒子、呼吸或镜头晃动。区分“代码时间一致”“画面已核对”“听感已核对”。
