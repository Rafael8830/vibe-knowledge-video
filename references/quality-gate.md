# 质量门：看图改图 + 数字纪律

> `qa_check.py` 能查出统计异常（规格、暗场占比、节奏、削波），但查不出**"观众看不看得懂"**。机器过检 ≠ 可以交片。本文档是成片前的最后一道人工关卡，分三部分：看图改图、终检三遍、数字纪律。

## 1. 为什么必须看图，不能看代码

"代码逻辑没问题"不构成任何证据。渲染出的画面几乎总有第一轮看不出的毛病：字被辉光冲淡、标注压住主体、转场中间有说不清的帧。这类片子是**看着图改出来的**——标准工作流是：

```
渲染 → 拼图总览 → 逐帧挑毛病 → 修复 → 重截同样的时刻 → 确认修好且没改坏别处 → 再来一轮
```

**至少两轮。** 第一轮改完重截同样的时刻；还有毛病就再来一轮。带着自己都看得出的毛病交片，等于把质检成本转嫁给观众。

## 2. 三个看图工具（v2 渲染器新增）

```bash
# 全片均匀 16 帧拼成一张总览图（看全局节奏、风格是否统一）
python3 scripts/render_frames.py index.html review/ --duration 130 --sheet 16

# 指定时刻拼一张（检查关键节点）
python3 scripts/render_frames.py index.html review/ --duration 130 --sheet 3.5 18 62 95

# 原尺寸单帧（检查细节：字号、重叠、辉光）
python3 scripts/render_frames.py index.html review/ --duration 130 --stills 18.3 62.4

# 某个转场区间均匀取 12 帧拼图（检查转场是否说得清）
python3 scripts/render_frames.py index.html review/ --duration 130 --motion 61.5 64
```

看图顺序：先 `--sheet 16` 看全局，再对可疑镜头 `--stills` 看细节，最后对每个转场 `--motion` 过一遍。

## 3. 毛病对照表（看图时逐条对）

| 看到什么 | 多半因为 | 改法 |
|---|---|---|
| 主体小小地缩在中间 | 尺寸按"画得下"定的 | 主体占画面宽六成以上，最小可辨单元 ≥ 20px，反推缩放 |
| 遮住字幕认不出画面是什么 | 画成了抽象记号 | 加体积与材质（明暗/高光/厚度），或从一个人人认得的画面推进去；还不行就换形象 |
| 字幕里说的名词，屏上找不到 | 分镜漏了 | 画出来，或改句子。开场最容易犯 |
| 一大片发白、发糊 | 实心大色块吃了辉光 | 有体积的实物画在不参加辉光的底层；或这段把辉光强度调低 |
| 渐变上有一圈圈硬边 | 半透明叠层太少 | 多叠几层、每层更淡，或直接用径向渐变 |
| 东西是平的，像贴纸 | 没有明暗 | 靠边压暗、受光面提亮、背后垫一层极淡的底 |
| 小字压在主体上 | 标注随手放 | 拉到主体外，细引线连过去；一镜最多一条小字 |
| 线条或物体伸进字幕带 | 推近时带进来了 | 该区域元素随景深淡出；字幕带（约 82%–95%）保持干净 |
| 一句字幕里画面变了三四处理 | 贪多 | 拆成两句，或删掉次要变化。每句只改一处 |
| 连着几句画面完全没变 | 没设计"那一处变化" | 回分镜表补；但结论/引文句停住是合法的，别误伤 |
| 转场中间有几帧说不清在干什么 | 两个状态硬插值 | 换成一个叫得出名字的动作（钻进去/拼起来/倒放回去），或把转场压到半秒内 |
| 推近镜头先漂移后猛冲 | 缩放线性插值 | 缩放在对数空间插值，焦点按 1/缩放 走 |
| 和参考片并排看，自己的又暗又空 | 主体不亮不大 | 主体放大、给颜色和体积；背景可以暗，主体不能暗 |
| 一秒里两样东西同时在动 | 没有主次 | 每一刻只有一个主体在动，其余降到三成亮度或离场 |

## 4. 终检三遍（全片渲完后）

1. **静音、遮住字幕看一遍**：每一段在讲什么，看得出来吗？
2. **只读字幕看一遍**：通顺吗？有哪句的名词屏上找不到吗？
3. **对照门槛表**：

| 维度 | 门槛 |
|---|---|
| 讲解 | 成片与分镜表对得上；随机抽五镜都能过三问；没有纯配图的段落；屏上的数前后一致；尺子和道具回过场 |
| 画与不画 | 提问、命名、结论没有硬配图；也没有连着几句画面死停 |
| 结构 | 片名在 6–24 秒出现；结尾回到开头画面；最后一屏是片名+引用 |
| 字幕 | 每句一行不换行；强调克制（见 copywriting-rules §5）；字幕带无杂物 |
| 画面 | 任何一刻只有一个主体在动；色彩含义全片一致；没有东西伸进字幕带 |
| 节奏 | 无硬切（除有意的少量闪切）；主体出完停住让人读；每 20–30 秒有纯画面段 |
| 事实 | 屏上每个数字与事实表一致；每站有出处；示意已标注 |
| 技术 | 渲染确定性通过（同帧两次渲染一致）；1920×1080 / 30fps；无多余水印 |

不合格的时间点列成清单，修复后**只重渲对应片段**确认，再出全片。

## 5. 数字纪律（本风格"可信感"的来源）

1. **先算，后写。** 屏上出现的每个数字，先由代码算出来（或从权威来源查到并记入 NOTES.md），再写进文案。禁止先写个好看的数再倒推。
2. **屏上的计数是真的。** "掷了一万次"的画面里，计数器就要真数到一万（载入时用固定种子把整场模拟算完存成表，每帧查表回放）。观众能感觉到"这是真在算"。
3. **固定种子。** 所有随机数来自带种子的发生器，同一帧渲两遍必须一模一样——这是逐帧渲染器和"只重渲一段"的前提。
4. **模拟要标注。** 模拟数据在画面上标"模拟"或"示意模拟"；示意曲线标"示意"。
5. **结论数字来自计算。** 曲线的峰值、命中率、百分比由代码得出；若文案里的数字与计算结果不符，改文案，不改数据。
6. **可核验性（进阶）**：把关键计算抽成纯函数并配断言测试（数值、单调性、边界），渲染前跑一遍。页面里可暴露 `window.selftest()` 返回 `{name, ok, got, want}` 列表供 CI 或 QA 调用。

## 6. 交片诚实条款

交付时如实说明：还有哪些不满意的地方、哪些段落没逐帧看过、哪些数字是示意。宁可在交付说明里列三条待改，也不要让观众发现一条。
